# Mount data table (ids 0–255)

Per-id reference combining the file-id table and the client's own mount names,
plus the `key_item` column (`3072 + id`). For the mechanism behind these numbers
see [mechanism.md](mechanism.md); for the `xi mount` commands see [README.md](README.md).

Source of truth: generated by reading `VTABLE.DAT`/`FTABLE.DAT` (+ ROM2–ROM10
overlays) and the `ROM/351/84.DAT` mount-name table directly from the client install
(mirrors the repo-root `mount_file_ids.csv` / `mountlist.txt`).

## Columns

- **mount_id** — value the server puts on the player (`uint8`, 0–255).
- **mount_name** — the client's name from `ROM/351/84.DAT` (blank = not a real mount).
- **is_mount** — `yes` for the 39 shipped mounts (0–38), `custom` for project custom mounts,
  `no` otherwise.
- **key_item** — owns/unlocks it: `3072 + mount_id` (`CHOCOBO_COMPANION = 3072`).
- **formula** — `0x019131 + mount_id`.
- **file_id** / **file_id_dec** — resulting FTABLE file-id (hex / decimal).
- **rom_dat_file** — what that file-id points at today (`null` = free slot).

## Notable rows

- **id 33 (Noble Chocobo)** — `null` slot; reuses the chocobo model.
- **id 63** — chocobo placeholder (`ROM/351/104.DAT`), parked in the last slot; no name, never shows.
- **Free, namable slots inside the 64-table: 39–62** (63 occupied). Project custom mount **50**
  is currently claimed by **Cyakko** and should stay id 50 to avoid repatching when retail fills
  lower reserved slots.
