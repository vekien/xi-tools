# xi dll &lt;target&gt; pack

Re-compress an edited `.text` back into POL1 and emit a **game-loadable** packed
DLL. This is the inverse of [`unpack`](unpack.md) and the final step of any
binary change to `FFXiMain.dll`, `polcore.dll`, or `app.dll`.

Available for every target (generated by `make_pack_cmd()`):

```
uv run xi dll ffximain pack --unpacked misc/FFXiMain_unpacked.dll
uv run xi dll polcore  pack --unpacked misc/polcore_unpacked.dll
uv run xi dll app      pack --unpacked misc/app_unpacked.dll
```

---

## Usage

```
uv run xi dll <target> pack [--template PATH] (--unpacked PATH | --text-bin PATH)
                            [--output PATH] [--verify/--no-verify]
```

| Option | Description |
|---|---|
| `--template PATH` | Original packed DLL — the PE shell + POL1 stub to rebuild into. Default: the resolved packed DLL ([list](list.md)). |
| `--unpacked PATH` | Unpacked PE whose `.text` gets re-compressed. |
| `--text-bin PATH` | Raw decompressed `.text` bytes — an alternative to `--unpacked` (e.g. output of [text-dump](text-dump.md)). |
| `--output PATH` | Output packed DLL. Default: `misc/<stem>_repacked.dll`. |
| `--verify / --no-verify` | Round-trip: decompress the result and compare to the input `.text`. **Default: verify.** |

Provide **either** `--unpacked` **or** `--text-bin` as the source of the new
`.text`. `--template` supplies everything else (headers, POL1 stub, entry point).

---

## What it does

`pack_dll()` (`src/xi/dll/pol1_io.py`):

1. Take the new `.text` (from `--unpacked` or `--text-bin`).
2. **LZSS-re-compress** it into the template's POL1 payload region.
3. Reset the packed `.text` header to `SizeOfRawData = 0` and leave the OEP on
   the decompressor stub — exactly as the retail file ships.
4. **Identity fast-path**: if the new `.text` is byte-identical to the
   template's own decompressed `.text`, reuse the original POL1 payload
   bit-for-bit (no re-compression).
5. With `--verify`, decompress the freshly-packed result and assert it matches
   the input `.text`.

## Example

```
uv run xi dll ffximain pack \
  --template "FFXiMain.dll" \
  --unpacked FFXiMain_patched.dll \
  --output "FFXiMain.dll"
```

```
Template        : FFXiMain.dll
.text in        : 3,283,456 bytes
POL1 payload max: 0xf4240 (1,000,000) bytes
Stub RVA        : 0xbd0000
Stub dst size   : 0x321000
Compressed      : 812,004 bytes
Verify          : OK

Wrote packed DLL : FFXiMain.dll
  size           : 2,898,000
  EP RVA         : 0xbd1234
Done. Drop over game FFXiMain.dll to test (keep a backup).
```

If the payload doesn't fit the template's POL1 region, packing fails — keep
edits **same-length** (pad with NOPs) so the compressed size stays within the
original envelope. This is why the [inventory patch](../ffximain/inventory.md)
never grows an instruction.

---

## Deploying

1. **Back up** the live DLL first.
2. Copy the packed output over the game file.
3. **Full client restart** — the DLL is mapped at launch.

Never deploy an [unpacked](unpack.md) PE; only the packed output is loadable.
