# `ROM/165/84.DAT` — Zone Name Table

The master **list of zone names**, indexed by zone ID. This is the authoritative
source for the *Name* column in [../zone/zones.md](../zone/zones.md): entry *N* is
the display name of zone *N* (e.g. `245` → `Lower Jeuno`). xim reads it as
`ZoneNameTable` (`zoneNameTable.first(zoneId)`).

It is a **`d_msg` string table** — the same container FFXI uses for all its text
DATs (dialog, item descriptions, menus, …), so the format below is reusable.

- **300 entries** (zone IDs `0`–`299`). Blank entries exist for unused slots.
- Strings are **XOR-encrypted with `0xFF`** (a per-table bit-mask byte).
- Single-language: each block holds one string (the zone name).

## File format (`d_msg`)

```
offset  size  field
0x00    8     magic "d_msg\0\0\0"
0x08    8     (flags — language/format; 01 00 01 00 03 00 00 00 here)
0x10    u32   unk0            (= 3)
0x14    u32   fileSize        (= 19984)
0x18    u32   tableOffset     (= 0x40)   start of the offset table / encrypted region
0x1C    u32   tableSize       (= 2400 = numStrings*8; 0 => "without-table" layout)
0x20    u32   stringBlockSize (= 0; used only by the without-table layout)
0x24    u32   stringSectionSize (= 17520)
0x28    u32   numStrings      (= 300)
0x2C    u32   unk1            (= 1)
0x30..  pad   zeros to tableOffset
```

Everything from `tableOffset` to `fileSize` is **XOR'd with `0xFF`**; un-mask it
before reading. Two layouts exist (chosen by `tableSize`):

- **With offset table** (this file, `tableSize != 0`): at `tableOffset`, an array of
  `numStrings` × `{ offset:u32, unk:u32 }`. String blocks begin right after it, at
  `stringStart = tableOffset + numStrings*8`. Block *i* is at `stringStart + offset[i]`.
- **Without table** (`tableSize == 0`): block *i* is simply at
  `tableOffset + stringBlockSize*i`.

### String block

```
u32         stringsInBlock                  (1 for zone names)
{u32,u32}[] per-entry { offset:u32, flag:u32 }   (relative to block start)
...
per entry at block_start + offset:
  u32   marker        (1 = string present, else empty)
  if marker == 1:
    skip 0x18 bytes   (per-string metadata)
    zero-terminated ASCII string
```

Multi-string blocks (used by other `d_msg` tables, e.g. dialog with gender/plural
variants) hold several entries per block; for zone names there is just one.

## Reading it (xi)

xi has no `d_msg` command yet, but the table is trivial to read — see the
verification script summarized in [../zone/zones.md](../zone/zones.md#verification-against-the-client-filetable).
Minimal decode:

```python
import struct
b = bytearray(open("ROM/165/84.DAT", "rb").read())
assert b[:5] == b"d_msg"
unk0, fileSize, tableOffset, tableSize, blockSize, sectionSize, numStrings, unk1 = \
    struct.unpack_from("<8I", b, 0x10)
for i in range(tableOffset, fileSize):       # un-mask
    b[i] ^= 0xFF

def block(start):                            # first string in a block
    n = struct.unpack_from("<I", b, start)[0]
    if n == 0: return ""
    off = struct.unpack_from("<I", b, start + 4)[0]
    p = start + off
    if struct.unpack_from("<I", b, p)[0] != 1: return ""
    p += 4 + 0x18
    return b[p:b.index(0, p)].decode("latin1")

offs = [struct.unpack_from("<I", b, tableOffset + i*8)[0] for i in range(numStrings)]
sstart = tableOffset + numStrings*8
names = [block(sstart + offs[i]) for i in range(numStrings)]
# names[245] == "Lower Jeuno"
```
