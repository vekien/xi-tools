# ROM/0/25.DAT — Character Selection Control Variant (`sel_`)

**Path:** `ROM/0/25.DAT`  
**Size:** 3,808 bytes (0x0EE0)  
**Magic:** `sel_`  

This file is another small `sel_`-format control/scene file adjacent to `ROM/0/24.DAT`.
It has the same overall format family, but includes more `s###` records and a slightly denser
control section.

Current best interpretation: this is a companion title/login or character-selection scene
controller, likely covering a different state, layout, or motion set than `ROM/0/24.DAT`.

## Common record shape

Like `ROM/0/24.DAT`, the `s###` blocks follow the same keyframe layout:

```
+0   char[4]   tag          e.g. "s101"
+4   uint32    type         usually 0x00000486, sometimes 0x00000606
+8   24 bytes  zeros        reserved / padding
+32  uint32    key_count    number of 0x30-byte keyframes
+36  uint32    flag         often 0 or 1
+40  ...       keyframes    key_count * 0x30 bytes
```

The first three floats in each keyframe are position-like `(x, y, z)` values. Example: `s101` starts
at `0x0320`; its first keyframe position starts at `0x0350` and its second starts at `0x0380`.

Notable repeated constants:

| Value | Meaning |
|---|---|
| `0x43AF0000` (`350.0f`) | repeated in many `s###` records; likely a shared scene parameter |
| `0x3F800000` (`1.0f`) | common record terminator / flag |
| `0x3F2AAAAA` (`0.666...f`) | appears in some `0x00000606` records |

Several records come in pairs with similar values, reinforcing the idea that these are scene
states, camera/object anchors, or key transforms rather than simple menu positions.

## Control section

Unlike `24.DAT`, the ordering of the control blocks is different:

- `loop` appears first at `0x0A40`
- `mov2` follows at `0x0AD0`
- `suny` appears at `0x0B30`
- `mov1` begins at `0x0B50`
- `main` appears late at `0x0E30`
- `end` is at `0x0ED0`

This means the file is still a compact scene-state script, but its internal organization differs
from `24.DAT`.

```
0x0E5C  01 00 00 00
...
0x0EA0  73 05 00 00  00 00 00 00  "loop"
```

So `main` again appears to dispatch the looped control flow rather than holding transform data.

## What this file is not

Direct evidence argues against these interpretations:

- Not a texture DAT: no texture names, TXD headers, or image payloads.
- Not the `menu` format from `ROM/0/1.DAT`: no `menu    ` sections or 2D packed UI elements.
- Not an external movie-file reference list: no `.pmv`, `.bgw`, `mov999`, or `music999` strings.
