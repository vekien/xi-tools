# ROM/3/25.DAT — Home Point (effect-only entity)

**Path:** `ROM/3/25.DAT`
**Type:** Entity DAT — invisible actor proxy + a seven-resource particle effect
**Size:** 77,120 bytes (CatsEyeXI client), 41 sections
**Resolves from:** `look` size 0 (standard), `modelid 51` → `file_id = 51 + 1300 = 1351`

The Home Point crystal. Worth documenting not because Home Points matter but
because this is the **cleanest example of an effect-only entity** in the game: a
model whose visible form is entirely `0x05` generators, with no body mesh at all.
104 NPC models in `mv/lists/npcs.json` are built this way — portals, telepoints,
lightbeams, vortexes, and every elemental.

See [../fx/particle_mesh.md](../fx/particle_mesh.md) for the `0x1F` format,
[../fx/effects.md](../fx/effects.md) for `0x05` generators, and
[../entity/npc-look.md](../entity/npc-look.md#effect-only-entities) for the pattern.

> **Version note.** The 77,120-byte figure and the section offsets below are the
> CatsEyeXI client's copy (SHA-256 `107a0ac5…0ff1c3`). Current retail ships the
> same 41 sections in the same order with **higher-resolution textures** —
> 172,352 bytes, `tayu` at 65,632 instead of 16,480. Structure is identical;
> sizes and offsets are not.

## The entity half is a decoy

| Section | Id | Payload | What it actually is |
|---|---|---|---|
| `0x29` Skeleton | `toum` | 4,656 B | 2 joints. **toumei** (透明) = "transparent" |
| `0x2A` SkeletonMesh | `hf_t` | 208 B | **1 joint, 3 vertices — one triangle ~3 mm across**, textured `black` (a 2×1 TIM) |
| `0x2B` Animation | `idl0` | 192 B | a **placeholder** idle clip — 99 frames of identity transforms, no keys |

That is the entire non-effect content. The proxy exists so the client's actor
system has something to place, target, click and pose — it is never meant to be
seen. A viewer that renders only `0x29`/`0x2A`/`0x2B` shows an empty stage, which
is exactly what XI Model Viewer did before it learned `0x1F`.

## The visible half: 5 meshes + 2 cards

| Resource | Type | Tris | Material | Geometry |
|---|---|---:|---|---|
| `wa␣␣` | `0x1F` | 48 | `bind␣␣␣␣tayu` | ground ring, X/Z ±1.08, **Y exactly 0** (flat on the floor) |
| `sil␣` | `0x1F` | 192 | `bind␣␣␣␣nami` | aura shell, X/Z ±0.60, Y −1.26‥0 |
| `naka` | `0x1F` | 24 | `bind␣␣␣␣tayu` | vertical cross planes, Z exactly 0, Y −1.94‥−0.48 |
| `bind` | `0x1F` | 30 | `bind␣␣␣␣kori` | **the crystal**, Y −2.185‥−0.025 = 2.160 tall (*kori* 氷 = ice) |
| `pou1` | `0x1F` | 2 | `bind␣␣␣␣pou` | flash quad, X/Y ±1 |
| `tama` | `0x21` | 2 | `bind␣␣␣␣tama` | 1 sprite card, ±2 |
| `tubu` | `0x21` | 4 | `bind␣␣␣␣tubu` | 2 sprite cards, ±1 |

302 triangles over seven resources. FFXI is **Y-down**, so the crystal's
−2.185 is its tip and `wa`'s Y=0 is the ground.

## Two routines, and `autorun` tells them apart

| `0x07` | Fires | Generators |
|---|---|---|
| `aper` | on load, all at t=0 | `snd0` `wa01` `wa00` `sil0` `bnd0` `nak0` `nak1` `tam0` `sil1` |
| `bind` | t=24 and t=58 frames | `pou1` `tub0` `pou0` `sil2` (+ sound `6023`) |

Every generator in `aper` sets **`genFlags` bit `0x10` (autoRun)**; every
generator in `bind` clears it. So "idle vs activation" is not an inference from
how the resources are grouped — it is a decodable flag, and it is the filter
`xi fx export --assemble` and the model viewer both use to draw the object at
rest.

The seven idle layers, with each generator's own transform and motion. Rotation
is `0x09`, spin is `0x0B` in radians per 60 Hz frame, scroll is sec3 `0x27`/`0x28`:

| Generator | Mesh | Position | Rotation | Scale | Spin | UV scroll | Blend |
|---|---|---|---|---|---|---|---|
| `wa00` | `wa` | 0,0,0 | — | 1.0, 1.0, 1.0 | **+0.0035** | −0.002 / +0.0035 | additive |
| `wa01` | `wa` | 0,0,0 | **52°** | 0.7, 0.7, 0.7 | **+0.0035** | −0.002 / +0.0049 | additive |
| `sil0` | `sil` | 0,0,0 | — | 1.0, 1.4, 1.0 | — | +0.002 / +0.0047 | additive |
| `sil1` | `sil` | 0,0,0 | **23°** | 1.3, 0.7, 1.3 | — | −0.0005 / +0.0049 | additive |
| `nak0` | `naka` | 0, −0.1, 0 | **30°** | 1.0, 1.0, 1.0 | — | +0.002 / +0.001 | additive |
| `nak1` | `naka` | 0, −0.1, 0 | **150°** | 1.0, 1.0, 1.0 | — | +0.001 / +0.002 | additive |
| `bnd0` | `bind` | 0, −0.1, 0 | — | 1.0, 1.0, 1.0 | **−0.0157** | +0.004 / +0.002 | blend (`0x1E` = 0x44) |

So the object is: **two concentric ground rings** turning slowly one way
(+0.0035 rad/frame ≈ +12°/s, `wa01` offset 52° from `wa00`), **two nested aura
shells** that only scroll their textures, **two cross planes** at 30° and 150°,
and **the crystal** turning the other way at −0.0157 rad/frame ≈ **−54°/s, one
turn every 6.7 s**.

`nak0`/`nak1` differ in *nothing but* their `0x09` rotation, so any dedupe keyed
on mesh + position + scale drops one of them and loses half the cross. Only
`bnd0` and `tam0` declare a BlendFunc at all; the rest fall through to
`Src_One_Add` — additive — which is why their vertex colours ramp from white to
black. See [../fx/effects.md](../fx/effects.md#what-moves-an-effect).

## The crystal has its own render path

`bnd0` is the only generator in the file that:

- sets **`0x01010000` in its StandardSetup flags** (the dword at StandardSetup+4,
  immediately before the `bind` mesh reference), and
- carries a **sec2 opcode `0x55` SpecularParams** entry.

Bit 24 of those flags is the selector. `CYyGenerator.cpp:150` branches on it:

```c
if ((pos[1] & 0x00200000) != 0)  elem = new CMoD3mSpecialElem();
else if ((pos[1] & 0x00100000) != 0)  elem = new CMoDistModelElem();
else if ((pos[1] & 0x01000000) != 0)  elem = new CMoD3mSpecularElem();   // <- 0x01010000
else  elem = new CMoD3mElem();
```

So the crystal genuinely gets a dedicated specular element class rather than the
common one. Its `0x55` payload is `3× f32`, then the DatId **`nami`**, then
`10.0`, `30.0`, a BGRA and a u32 — i.e. the specular reflection uses `nami` (波,
"wave") as an environment map, which is why `bnd0` references a texture it never
draws with. See [../fx/effects.md](../fx/effects.md#0x55-specularparams) for the
field layout.

## Sound

| Ref | Section id | Embedded id | File | Notes |
|---|---|---|---|---|
| `snd0` → | `9013` | **9013** | `sound/win/se/se009/se009013.spw` | ambient loop, 48 kHz, loop start 8288 blocks (`0x2060`) = 132,608 PCM frames |
| `bind` → | `6023` | **16023** | `sound/win/se/se016/se016023.spw` | activation one-shot, 48 kHz, `loop_start = -1` |

The activation section is **named `6023` but contains sound id `16023`**. Both
`se006023.spw` and `se016023.spw` exist on disk, so guessing from the section
name silently plays the wrong sound. `xi audio refs` reads the embedded `u32` and
gets it right — see [../audio/refs.md](../audio/refs.md).

## Reproducing

```bash
uv run xi fx json ROM/3/25                # 13 generators: mesh, transform, spin, uv_scroll
uv run xi fx export ROM/3/25 --assemble   # the idle crystal as one GLB
uv run xi audio refs ROM/3/25 --stdout    # both sounds, resolved
```

In XI Model Viewer, `ROM\3\25.DAT` is listed as **Home Point #1 (Effect)**.
