# ROM/118/115.DAT — Mission / Quest Text Database (`menu`)

**Path:** `ROM/118/115.DAT`
**Size:** 481,392 bytes
**Magic:** `menu`, version `01 01`
**Loaded:** at boot (see [dats_boot.md](../dats_boot.md)) — this is the **live** mission/quest
text file for the modern CatsEyeXI client.
**xiclient label:** `MENU_MissionQuest` in `LanguageDependentDats`, English file_id `0x52` / 82

This file holds the **per-category mission and quest text** shown in the in-game Missions/Quests
menus (mission names, "Mission Orders:" objective text, etc.). It is *not* the menu layout and
*not* the category labels — it is the body text for each storyline.

xiclient independently labels this language-dependent slot as `MENU_MissionQuest`. In the English
table, that slot is file_id 82, which resolves through FTABLE/VTABLE to `ROM/118/115.DAT`.

> **Important:** the legacy `ROM/0/1.DAT` `mis2`/`missionm` menu + the `ROM/97/41.DAT` XISTRING
> labels are the **vanilla-era** mission menu. This modern client does **not** load `ROM/0/1.DAT`,
> and `97/41` only covers content up to Aht Urhgan. The live mission system is this file.

## Text encoding — ROR-1 (rotate right 1 bit)

All text in this `menu`-format DAT is stored **rotated left 1 bit**; decode by **rotating each
byte right by 1 bit**. This is why plain-ASCII greps for "San d'Oria", "Mission", etc. find
nothing here — the bytes are bit-rotated.

```python
def ror1(b: bytes) -> bytes:                 # decode
    return bytes(((c >> 1) | ((c & 1) << 7)) & 0xff for c in b)

def rol1(b: bytes) -> bytes:                 # encode (and to build search needles)
    return bytes(((c << 1) | (c >> 7)) & 0xff for c in b)
```

Decoding the `sd_ms_e` section yields readable text, e.g.:

```
Mission 5 … The Three Kingdoms (San d'Oria) … Mission Orders: …
Mission 6 … The Three Kingdoms (Bastok)     … Mission Orders: …
```

To search for a string, encode it with `rol1()` first, then `bytes.find()`.

## Section layout

The file is a list of `menu    <tag>` sections (same section framing as other menu DATs). Each
section is one mission/quest log category. Within a section: the name, a small header
(`uint32 entry_count`, then per-entry offset records `{text_off, text_off2, …, index}`), then
the bit-rotated text blob.

### Categories present (14 + item table)

| Tag | Category | Tag | Category |
|---|---|---|---|
| `sd_ms_e` | San d'Oria **missions** | `sd_qs_e` | San d'Oria quests |
| `bs_ms_e` | Bastok missions | `bs_qs_e` | Bastok quests |
| `ws_ms_e` | Windurst missions | `ws_qs_e` | Windurst quests |
| `zl_ms_e` | Rise of the Zilart missions | `jn_qs_e` | Jeuno quests |
| `pr_sc_e` | Chains of Promathia (scenario) | `fr_qs_e` | (Jeuno/other) quests |
| `at_ms_e` | Treasures of Aht Urhgan missions | `ot_qs_e` | Other-areas quests |
| `as_ms_e` | Assault missions | `at_qs_e` | Aht Urhgan quests |
| `sc_item_` | (item/support table) | | |

`_ms_e` = missions, `_qs_e` = quests, `_sc_e` = scenario, trailing `_e` = English. A full scan of
all `menu`-magic DATs found these mission section tags **only in this file**.

### What's *not* here

The newer storylines shown in the in-game menu — **Wings of the Goddess (Campaign)**,
**Rhapsodies of Vana'diel**, and the **Add-on scenarios** (A Crystalline Prophecy, A Moogle Kupo
d'Etat, A Shantotto Ascension) — have **no `_ms`/`_sc` section here**. Their text uses a
different/later mechanism (not located in a `menu`-tagged DAT; likely `d_msg` tables or
server-delivered). The expansion **display names** come from a separate source (below).

## Where the menu *labels* come from (vs. this file)

| Menu element | Source |
|---|---|
| Mission **body text** (objectives, mission names) | **this file** (`118/115`), ROR-1 encoded |
| Expansion **display names** (Rise of the Zilart … Rhapsodies of Vana'diel) | auto-translate **Expansions** category in `ROM/168/25.DAT` (plain ASCII, boot-loaded) — see [ROM_168_25.md](ROM_168_25.md) |
| Top-level **group labels** (Nations, Zilart, Promathia, Aht Urhgan, Altana, Adoulin, Add-ons) | **not found in any DAT or FFXiMain.dll** (searched plain + ROR-1) — appear to be built/hardcoded in the client |

### Sibling files in the `ROM/118/11x` family

* **`ROM/118/113.DAT`** — the **Japanese** mission/quest text (same section tags without the
  `_e` suffix: `sd_ms`, `bs_ms`, `zl_ms`, `pr_sc`, `as_ms`, `*_qs`). Sibling of this file.
* **`ROM/118/114.DAT`** — `menu`-magic but **not** mission text: boot-loaded numeric tables
  (`mnc2`/`mon_`/`levc`/`mgc_`/`comm`). It is heavily read during boot, but FFXiMain xrefs point to
  model/action-style lookup data rather than 2D title-menu layout.
* **`ROM/118/111.DAT`** — main in-game UI widget/texture sheet (gauge, compass, itemslot, fonts…).
* **`ROM/118/112.DAT`** — `lobb` lobby/logo textures.
* **`ROM/118/116.DAT`** — `mgc_` icon data.

See [../dat_index.md](../dat_index.md) for the full family rundown.

## Editing missions

To edit existing mission text: locate the section (`sd_ms_e`, etc.), `ror1`-decode the blob,
edit, `rol1`-re-encode, and write back (keeping entry offsets/lengths consistent). Adding a
brand-new storyline category is much harder — there is no `_ms` section for the newer
expansions, the top-level group labels aren't data-driven here, and mission *progression* is
governed by the LSB server at `D:/xi-server/server`, not this text file.
