# ROM/0/14.DAT – ROM/0/21.DAT — Window Skins (`win0`)

**Paths:** `ROM/0/14.DAT` … `ROM/0/21.DAT` (8 files)
**Size:** 10,880 bytes each (identical)
**Magic:** `win0`, version `01 01` (1.1)

These eight files are the **window background skins** — the frame/background art used to draw
every in-game window (menus, chat log, status, etc.). They correspond to the eight
user-selectable **"Window" designs** in the FFXI config screen. Each file is one complete skin.

The eight files are structurally identical (same format, same four sub-textures) but differ in
pixel content — each is a distinct visual design.

---

## What's in each file — 4 textures (9-slice tile set)

Every skin is a **9-slice** frame built from four DXT1+alpha textures:

| Texture | Size | Role |
|---|---|---|
| `newtex` | 128×128 | Center **background fill** (tiled across the window interior) |
| `corner` | 32×32 | **Corner** piece (mirrored into all four corners) |
| `hfr1` | 32×32 | **Horizontal frame** — top & bottom edges (tiled/mirrored) |
| `vfr1` | 32×32 | **Vertical frame** — left & right edges (tiled/mirrored) |

All four are **DXT1 with 1-bit alpha** (`DXT1+alpha`). The engine composites them at runtime:
the four corners + four edges + tiled center scale to any window dimensions, which is why a
single 128×128 + three 32×32 tiles can dress windows of any size.

> The internal order of the four textures varies between files (e.g. `14` starts with `newtex`,
> `18` starts with `corner`), but the set is always the same four.

---

## Container format (`win0`)

```
+0x00  char[4]   magic        "win0"
+0x04  uint8     ver_major    0x01
+0x05  uint8     ver_minor    0x01
+0x06  ...        padding (zeros to 0x20)
+0x20  section[]  four texture sections, packed sequentially
```

Each texture is a standard FFXI menu-texture section: a 4-char tag + `menu    <name>` label
(e.g. `newt` / `"menu    newtex"`), a small image descriptor (width, height, pixel format), a
`…TXD` data marker, then the raw DXT block data. The sections sit back-to-back; for `ROM/0/14`
the four `txd` payloads begin at offsets `0x000069`, `0x0020c9`, `0x002329`, `0x002589`.

## Extracting / editing

The `xi ui` tooling reads and writes these containers directly:

```bash
# List the textures in a skin
uv run xi ui tex export "ROM/0/14.DAT" --list

# Extract all four textures to .dds (DXT1) files
uv run xi ui tex export "ROM/0/14.DAT" --output-dir exports/ui/win0_14

# Re-import edited .dds files back into the container
uv run xi ui tex import  "ROM/0/14.DAT" exports/ui/win0_14
```

> Paths relative to the FFXI dir resolve against `FFXI_DIR` (the CatsEyeXI overlay, which does
> not contain these files). Pass the **absolute path** to the base-game ROM, e.g.
> `"<FFXI_DIR>/ROM/0/14.DAT"`, or copy the file locally.

When editing, keep each texture's dimensions and DXT1+alpha format; replacing a skin is simply a
matter of repainting the four tiles. Keep the alpha (corners/edges rely on it for the rounded
frame shape).

---

## Notes

- These are the **base-game** window skins. Re-skinning the UI = editing these eight files (or
  overriding them via the CatsEyeXI overlay DAT path).
- Distinct from the **UI texture sheets** (`ROM/119/51.DAT` fonts/cursors/buttons,
  `ROM/280/15.DAT` menu icons) and from the **menu layout** (`ROM/0/1.DAT`, section structure).
  A window's *position/size* comes from the menu layout; its *appearance* comes from the
  selected `win0` skin here.
